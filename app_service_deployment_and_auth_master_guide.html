Domain 3: Compute & App Services

App Service Deployment & Authentication Architecture

Comprehensive end-to-end breakdown: The SCM/Kudu engine, Web Deploy, FTP vs FTPS, deployment credentials, Basic Auth deprecation, and built-in RBAC roles.

🎯 30-Second Exam Cheat Sheet:
• Developer Least Privilege: Always assign Website Contributor (never Owner/Contributor).
• Modern Deployments: Web Deploy + Microsoft Entra ID (Bearer token over port 443). Enforces MFA and RBAC.
• Legacy Deployments: FTP/FTPS & Publish Profiles use Basic Auth (static passwords). Insecure, no MFA, high risk.
• Modern Security Baseline: Disable Basic Auth on basicPublishingCredentialsPolicies/ftp and /scm.
• SCM vs SCIM: SCM = Source Control Management (App Service Kudu). SCIM = Identity sync for Entra ID users to SaaS apps.

1. The Under-the-Hood Anatomy: Public Site vs. SCM "Kudu" Twin

When you deploy an Azure App Service web app named PortalApp, Azure secretly provisions two web endpoints backed by the same storage:

┌────────────────────────────────────────────────────────────────────────┐ │ Azure App Service Hosting │ ├───────────────────────────────────┬────────────────────────────────────┤ │ 1. Public Workload Endpoint │ 2. Secret Management SCM Twin │ │ https://portalapp.azurewebsites.net │ https://portalapp.scm.azurewebsites.net │ ├───────────────────────────────────┴────────────────────────────────────┤ │ Under-the-hood File System: │ │ Windows: C:\home\site\wwwroot\ (HTML, JS, Binaries, Configs) │ │ Linux: /home/site/wwwroot/ │ └────────────────────────────────────────────────────────────────────────┘

The public endpoint is what end-users hit. The SCM (Source Control Management) site, powered by the open-source Kudu service, is the administrative backdoor. It provides:

  • Deployment Engine: Receives Web Deploy, Git, ZIP Deploy, and GitHub Actions payloads.
  • Interactive Debug Console: PowerShell / Bash terminal directly inside the running container or sandbox.
  • Process Explorer & Diagnostic Logs: Live process memory dumps, streaming execution logs.

2. FTP vs. FTPS: Why Cloud Security Rejects It

FTP (File Transfer Protocol) was invented in 1971. While familiar to webmasters, it represents an anti-pattern in modern enterprise cloud architecture.

Protocol Ports Used Data Encryption Authentication Type AZ-104 Exam Assessment
Plain FTP Port 21 ❌ Plaintext (Zero encryption) Static Username + Password Strictly Forbidden: Credentials and source code transmitted cleartext over internet.
FTPS (FTP over SSL/TLS) Port 990 (Implicit) or Port 21 (Explicit) ✅ Encrypted via TLS Static Username + Password Legacy / Insecure: Encrypted in transit, but still uses Basic Auth. No MFA, no Entra ID, all-or-nothing access.

Fatal Flaws of FTP/FTPS on the Exam:

  1. No Entra ID Integration: You cannot log into an FTP client using your corporate Azure identity (user@company.com).
  2. Zero MFA Support: FTP clients cannot prompt for mobile push notifications or FIDO2 hardware keys.
  3. All-or-Nothing Blast Radius: An FTP user has unrestricted write/delete access across the entire wwwroot directory.

3. Web Deploy (MSDeploy): The Enterprise Standard

Web Deploy (Microsoft Web Deployment Tool) was created by Microsoft to package, synchronize, and deploy web applications directly over HTTPS (Port 443).

  • Delta Sync: Only transfers files that have changed since the previous deployment, minimizing downtime and bandwidth.
  • SCM Integration: Connects to https://<app>.scm.azurewebsites.net/msdeploy.axd.
  • Entra ID Authentication: Developers logging in from Visual Studio or Azure CLI authenticate with their personal Microsoft Entra ID account, satisfying zero-trust requirements.

4. The Three Deployment Credential Models

Azure App Service supports three credential tiers:

1. Microsoft Entra ID (Recommended): Developer (alice@corp.com) ──[Entra ID MFA]──> OAuth Token ──> Web Deploy (Port 443) ──> App Service (Audited, Least Privilege, Zero Static Passwords) 2. Application-Level Credentials (Publishing Profile): Developer ──[*.PublishSettings XML File with $app password]──> App Service (Scoped to 1 App, Static Password, No MFA) 3. User-Level Deployment Credentials: Developer ──[Single Username/Password set in Portal]──> ANY App Service in Subscription (High Blast Radius, Subscription-wide, Legacy)

5. Disabling Basic Auth & Enforcing Zero-Trust

In modern Azure tenants, organizations enforce policies to turn off basic credentials completely:

  • basicPublishingCredentialsPolicies/ftp: Set to false to disable all FTP/FTPS access.
  • basicPublishingCredentialsPolicies/scm: Set to false to force all deployments to use Entra ID tokens (blocks publish profiles).
# Azure CLI: Permanently block Basic Authentication deployments
az resource update --resource-group rg-prod --name ftp \
  --resource-type basicPublishingCredentialsPolicies \
  --parent sites/PortalApp --set properties.allow=false

az resource update --resource-group rg-prod --name scm \
  --resource-type basicPublishingCredentialsPolicies \
  --parent sites/PortalApp --set properties.allow=false

7. SCM vs. SCIM: Never Confuse These Acronyms

Feature SCM (Source Control Management) SCIM (System for Cross-domain Identity Management)
Azure Service Azure App Service Microsoft Entra ID
Purpose Deployment engine & debug console (Kudu) Automated user provisioning protocol
Endpoint https://<app>.scm.azurewebsites.net https://<saas-app>/scim/v2/Users
Example Use Uploading web app code and viewing logs Syncing employee accounts into Slack, Zoom, Salesforce

8. Exam Question Scenarios & Distractor Dissection

Exam Scenario: "The development team plans to publish updates to PortalApp using Web Deploy. They must authenticate using their Microsoft Entra ID accounts. The solution must follow the principle of least privilege."
  • ❌ Distractor: Owner / Contributor — Allows deleting the app and changing permissions. Violates least privilege.
  • ❌ Distractor: User-level FTPS Credentials — Uses basic auth, subscription-wide blast radius, does not use Entra ID.
  • ❌ Distractor: Application-level FTPS Credentials — Does not use Entra ID accounts, lacks MFA.
  • ✅ CORRECT: Website Contributor — Provides deployment and web app management rights with zero IAM or plan scaling permissions.
